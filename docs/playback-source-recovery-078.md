# CinemaHall TV 0.7.8: восстановление источника

Пользователь по-прежнему выбирает качество и озвучку. Номера файлов, раздачи и технические повторы скрыты внутри провайдера.

## Поведение

- Каждый ответ списка потоков получает отдельную сессию. После получения первых видеобайтов выбранный поток закрепляется за вариантом. Повторные открытия и HTTP Range-запросы возвращают тот же адрес TorrServer, без повторного ранжирования источников.
- При сетевой ошибке или зависшем буфере Media3/MPV могут автоматически заменить источник два раза. Новый адрес содержит номер попытки: повторное открытие этого адреса не расходует следующую попытку. Уже отказавшие источники исключаются внутри сессии.
- Для замены сохраняются качество, нормализованное название студии и технологические признаки выбранного источника. В режиме «Авто» эти ограничения закрепляются после первого успешного приготовления. Первый запуск «Авто» сохраняет существующий подбор рекомендуемого варианта.
- Позиция переносится в абсолютных миллисекундах через штатное переключение плеера. Снимок с нулевой позицией отказавшего движка не перезаписывает сохранённый прогресс.
- Если пользователь переключил встроенную озвучку на другую студию, повторный URL исходной студии не используется. При исчерпании попыток кнопка повтора открывает обычный выбор качества и озвучки.
- Пауза и фон не запускают автоматическое восстановление. Для начального ожидания остаётся предел 60 секунд; после первого кадра — 30 секунд без продвижения буфера или 90 секунд непрерывной буферизации. MPV сбрасывает интервал при нормальном воспроизведении, паузе и ожидании перемотки.

## Подготовка

Все страницы серверного поиска делят один лимит 20 секунд. Проверка конфигурации входит в этот лимит и ограничена пятью секундами. Весь запрос подготовки, включая поиск и запуск движка, ограничен 45 секундами. Уже полученные кандидаты сохраняются при отказе следующей страницы. Неверные и повторные курсоры не создают цикл.

Сетевые обращения выполняются вне общей блокировки кэша. Одинаковые запросы объединяются; одновременно допускается до четырёх разных поисков. Кэш содержит восемь записей, до 600 кандидатов на запись. Незавершённый поиск обновляется раньше завершённого; возраст аварийно возвращённого кэша не продлевается.

Файл серии выбирается по однозначному имени или карте эпизодов. Суффикс должен совпадать с границей пути; `1001.mkv` не совпадает с `001.mkv`. Два совпадения или противоречие между картой и номером серии в имени дают отказ кандидата. Для фильма сохраняется выбор самого большого видео, исключая sample.

## Проверка и границы

`tests/SourcePreparationCheck.java` запускается отдельно и из полного `ProviderCheck`. Проверяет общий дедлайн страниц, частичный результат, курсоры, исключение отказавших источников, два идемпотентных повтора, сохранение параметров и неоднозначность файлов. Локальный HTTP-сервер проверяет запрет редиректов и жёсткий срок для медленно поступающего тела ответа. `CinemaPlaybackPolicyTest` проверяет URL, ограничения повтора, студию, кодирование HDR10+, таймер буфера и перенос позиции.

Закрепление хранится в памяти провайдера для последних восьми списков потоков. Истёкшая сессия требует нового выбора, вместо скрытой подмены файла. Старые URL из предыдущих версий остаются совместимыми, но не получают восстановления сессии.

Совпадение студии и технологий основано на метаданных источника: это не подтверждение дорожки через ffprobe. Разные монтажные версии могут иметь разный тайминг; сопоставления сцен пока нет. Автоматическое восстановление после ошибок декодера сохраняет существующую политику движков. Физическая проверка на Xiaomi TV и обновление поверх установленного APK со стабильной подписью остаются отдельными задачами. Изменения сервера и подключение Lampac-провайдеров этот PR не выполняет.
