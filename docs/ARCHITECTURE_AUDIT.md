# CinemaHall — технический аудит (27 октября 2026)

## Что действительно работает

- GitHub Actions принимает `KINOAPI_KEY` только как секрет, делает JSON-индекс без ключа; тесты и первые две сборки успешны.
- KinoAPI — основной источник русскоязычного каталога, связей Kinopoisk/TMDB/IMDb/MAL/Shikimori, рейтингов, постеров и справочных озвучек. Это **не** API видеопотоков: `/watch-options` содержит названия озвучек, но `legalLinks=false`.
- Cinemeta, TVmaze и AniList применяются только по точным идентификаторам и только для выборочного дополнения. TMDB (через `append_to_response`) активируется при отдельном `TMDB_READ_TOKEN`.
- Zona сообщает о предполагаемых источниках с разрешениями/озвучками; TorrServer отвечает за попытку воспроизведения выбранного файла. Запись в индексе ≠ проверенное 4K/HDR-видео.

## Корневые проблемы и принятые решения

1. **Electron вместо Android.** Streambert — React desktop с `preload.js` (десятки IPC-методов), `src/ipc/*` и `<webview>` на страницах фильма/сериала. Ни Electron IPC, ни его `<webview>` не работают в обычном Android WebView. Использование исходников как APK без адаптации невозможно. Решение: оставить React-визуальную основу, но перейти на Android runtime и Media3 для прямых проверенных потоков. Управление D-pad и касанием — отдельные обязательные тесты.
2. **Память/скорость на Xiaomi TV.** Приблизительно 2,4 ГБ RAM всего на телевизоре. Единовременная загрузка тысяч карточек, декодирование full-resolution постеров и тяжёлые анимации будут тормозить. Решение: `index.json` для первого экрана, `search.json` по требованию, порции по 250 тайтлов, максимум четыре порции в памяти. Для фактических изображений UI должен запрашивать размер по экрану и не декодировать 4K-оригинал для миниатюры.
3. **Ошибки связывания.** Слияние по имени создавало бы ложные фильмы; даже при совпадающем одном ID встречаются противоречивые Kinopoisk/IMDb. Решение: только устойчивые ID, не склеивать записи с несовместимыми TMDB/Kinopoisk/IMDb, фиксировать коллизии и различать их стабильными ключами поиска; MAL/Shikimori ID разных сезонов хранить отдельно. При сомнении лучше временно оставить дубликат, чем отдать пользователю чужие серии.
4. **Растянутые фоны.** Поле `cover` не подтверждает пропорции 16:9. Решение: `backdropVerified`; неподтверждённый фон показывать как градиент/размытую подложку, а не растягивать портретный постер.
5. **Озвучки ≠ источники.** KinoAPI сообщает описательные названия, Zona — заявленные варианты раздач, только плеер определит доступность и аудиодорожки. Решение: три разных состояния, нормализация названий студий без склейки разных исполнителей, вкладки качества с запасными источниками.
6. **Секрет не является API для приложения.** GitHub Secrets доступны Actions, но не установленному APK. Текущий JSON-артефакт хранится 14 дней и не имеет постоянного адреса. Для релиза нужно утвердить постоянный статический хост (с соблюдением условий источников) либо защищённый маленький прокси на VPS. Не вшивать общий ключ в APK. При HTTP-редиректах API-клиент сохраняет токен только в исходном HTTPS-хосте и порту.
7. **«Все API» не должно означать фан-аут на каждую карточку.** KinoAPI уже агрегирует много первичных источников, поэтому повсеместное дублирование TMDB/Cinemeta/AniList увеличило бы задержки и риск 429. Выборочное дополнение плюс кэш быстрее и устойчивее.
