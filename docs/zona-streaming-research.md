# Единый выбор качества и озвучки: Zona и открытые реализации

Дата проверки: 28 октября 2026 года. Это исследование для CinemaHall, а не описание неизвестного закрытого кода Zona. Ниже отдельно отмечены официальные сведения, пользовательские наблюдения, прочитанный исходный код и предлагаемые изменения.

## Что подтверждается про Zona

Официальная справка Android описывает общий раздел «Качество и озвучка» и различия возможностей источников. При зависании разработчики предлагают попробовать другой вариант с аналогичным качеством и озвучкой. Это подтверждает продуктовую модель: одинаковые потребительские параметры могут соответствовать разным вариантам доставки.

- [Официальная справка Android](https://az1.zona.pub/faq/general-questions).
- [Официальная диагностика зависаний](https://az1.zona.pub/faq/problems).
- [Отсутствующий язык/озвучка](https://az1.zona.pub/faq/general-questions/no-russian-language).

На 4PDA пользователи сообщают, что варианты появляются постепенно, иногда спустя 15–30 секунд после начала воспроизведения. Другие участники объясняют маленькие цифры возле озвучек как условные номера источников. Есть сообщения, что одна и та же озвучка с одного источника тормозит, а с другого работает. Это пользовательские наблюдения; принадлежность конкретного номера определённому сервису и внутренний алгоритм объединения не подтверждены разработчиком.

- [Постепенное появление вариантов](https://4pda.to/forum/index.php?showtopic=377461&st=10100).
- [Обсуждение номеров источников](https://4pda.to/forum/index.php?showtopic=377461&st=8320).
- [Разница воспроизведения между источниками](https://4pda.to/forum/index.php?showtopic=377461&st=11480).
- [Поздняя загрузка и сохранение выбора](https://4pda.to/forum/index.php?showtopic=377461&st=9260).
- [Изменение озвучки при смене качества](https://4pda.to/forum/index.php?showtopic=377461&st=9040).

Важно различать платформы. [Справка Windows](https://wz1.zona.pub/faq/problems) прямо описывает торренты и раздающих пользователей. Этого недостаточно, чтобы считать каждый вариант в Android/TV магнит-раздачей. Официальная Android-справка говорит о разных источниках; форумные объяснения упоминают и видеосервисы. Архитектуру закрытого Android-бэкенда по этим сообщениям установить нельзя.

По официальной Android-справке, высокие разрешения Zona используют AV1 и требуют соответствующего аппаратного декодирования. Это характеристика заявленных источников Zona, а не универсальное требование для любого 4K-файла. Для CinemaHall важна проверка реального кодека выбранного файла и возможностей телевизора.

## Что видно в открытом коде

### Torrentio / Stremio: индексировать файлы серии

В прочитанном `addon/crates/addon/src/infrastructure/repository.rs` Torrentio сериал ищется в таблице файлов по `imdbId + imdbSeason + imdbEpisode`. Таблица файлов связана с торрентами через `infoHash`; результат содержит `fileIndex`. `domain/stream_info.rs` передаёт индекс в объект потока. Это конкретный пример заранее подготовленного индекса файлов, а не повторного разбора всех раздач на телевизоре.

- [SQL поиска Torrentio](https://github.com/TheBeastLT/torrentio-scraper/blob/master/addon/crates/addon/src/infrastructure/repository.rs).
- [Формирование потока](https://github.com/TheBeastLT/torrentio-scraper/blob/master/addon/crates/addon/src/domain/stream_info.rs).
- [Архитектура аддона](https://github.com/TheBeastLT/torrentio-scraper/blob/master/addon/README.md).
- [Контракт Stremio `infoHash` / `fileIdx`](https://stremio.github.io/stremio-addon-sdk/api/responses/stream.html).

Индекс файла зависит от API движка: значение из одного контракта нельзя без проверки переносить в другой. Для нашего TorrServer используется его фактический `file_stats.id`.

### AIOStreams: название раздачи и реальные дорожки имеют разную надёжность

AIOStreams различает сведения, полученные проверкой файла, метаданные индексатора и данные аддона. Проверенные дорожки могут содержать язык, название, кодек и каналы. По одному `rus` нельзя установить студию озвучки. В обсуждении #797 автор объясняет ошибки определения языка по имени: слово может относиться к субтитрам. В #883 пользователи показывают ложное определение языка из самого названия эпизода.

Информация о дорожках сохраняется и используется при следующих запросах. Документация отдельно описывает ограниченное ожидание проверки перед первым запуском. Это полезнее, чем проверять все видео каждый раз при открытии страницы.

- [Документация форматов и надёжности media info](https://docs.aiostreams.viren070.me/reference/custom-formatter/).
- [Сохранение дорожек после первого чтения](https://docs.aiostreams.viren070.me/apps/media-server/).
- [Настройки проверки и ожидания](https://docs.aiostreams.viren070.me/configuration/environment-variables/).
- [Ответ автора о ложных языках, #797](https://github.com/Viren070/AIOStreams/issues/797).
- [Язык внутри названия эпизода, #883](https://github.com/Viren070/AIOStreams/issues/883).

### Jackett / Sonarr: поиск серии и поиск сборника сезона

Jackett унифицирует запросы разных индексаторов через Torznab; TV-поиск поддерживает отдельные параметры сезона и эпизода. В обсуждении Sonarr разработчик объясняет, что поиск отдельной серии может не вернуть сезонные сборники. Сообщение старое, поэтому оно не является описанием всех нынешних индексаторов; это показательный случай, который надо отдельно тестировать.

Для нас это означает два независимых пути поиска: конкретный эпизод и сборники соответствующего сезона/сериала. Их результаты объединяются после проверки фактического состава файлов.

- [Jackett, API и кэш](https://github.com/Jackett/Jackett).
- [Sonarr: отдельный поиск сезонных сборников](https://forums.sonarr.tv/t/sonarr-cannot-find-season-packs/25435).
- [FAQ Sonarr: обновление индекса и сопоставление релизов](https://wiki.servarr.com/sonarr/faq).

### TorrServer: получить файл и поток, а не каталог озвучек

В закреплённой у нас версии MatriX.147.1 прочитаны `server/web/api/route.go`, `stream.go`, `ffprobe.go` и `server/ffprobe/ffprobe.go`. API предоставляет поток выбранного файла. `/ffp/status` сообщает наличие внешнего ffprobe; `/ffp/:hash/:id` работает только при наличии этого отдельного исполняемого файла. Нельзя считать эту возможность доступной в нашем Android APK без проверки и нельзя подменять её API GStreamer из другой сборки.

В `stream.go` предзагрузка вызывается при параметре `preload`. Наш текущий URL содержит `play`, без `preload`. Поэтому снижение настройки `PreloadCache` само по себе не доказывает ускорение нашего старта. Уже реализованная проверка первых байтов и конечные таймауты решают другую задачу: обнаруживают источник, который не отдаёт данные. Они не гарантируют достаточную скорость всего фильма.

У anacrolix/torrent чтение ожидает данные, а отмена контекста и упреждающее чтение управляются отдельно. В документации libtorrent потоковый режим использует приоритеты срочных фрагментов: простой последовательной загрузки недостаточно для устойчивого воспроизведения.

- [Маршруты MatriX.147.1](https://github.com/YouROK/TorrServer/blob/MatriX.147.1/server/web/api/route.go).
- [Условие предзагрузки](https://github.com/YouROK/TorrServer/blob/MatriX.147.1/server/web/api/stream.go).
- [Проверка наличия ffprobe](https://github.com/YouROK/TorrServer/blob/MatriX.147.1/server/web/api/ffprobe.go).
- [Внешний ffprobe и предел ожидания](https://github.com/YouROK/TorrServer/blob/MatriX.147.1/server/ffprobe/ffprobe.go).
- [anacrolix Reader: отмена и readahead](https://github.com/anacrolix/torrent/blob/master/reader.go).
- [libtorrent: потоковые приоритеты](https://libtorrent.org/streaming.html).

## Целевая модель CinemaHall

Это предлагаемая архитектура следующего этапа. Она не выдаётся за уже реализованные возможности 0.7.4.

Пользователь выбирает серию, затем качество и озвучку в одном месте. Пункт `1080p · LostFilm · многоголосый` представляет несколько совместимых источников. При смене встроенной дорожки в уже открытом файле применяется внутреннее переключение без перезапуска видео; при смене файла/источника сохраняется позиция.

| Сущность | Что хранится |
|---|---|
| Произведение / серия | Проверенные внешние ID и канонические номера |
| Раздача | Infohash, провайдер, ссылка, наблюдаемые сиды, сроки обновления |
| Файл | Infohash + фактический индекс, путь, размер, соответствующая серия |
| Озвучка | Студия, язык, тип перевода; неизвестные значения остаются неизвестными |
| Аудиодорожка | Стабильный селектор дорожки внутри конкретного файла, исходное название, кодек, каналы, достоверность |
| Вариант просмотра | Серия + качество + озвучка, совместимые кандидаты и технологии |
| Наблюдение воспроизведения | Время первых байтов/кадра, скорость, остановки, причина неудачи и срок актуальности |

На сервере объединяются индексаторы, выполняются нормализация, сопоставление файлов, ранжирование и кэширование. На телевизоре остаются интерфейс, декодирование и минимальный локальный торрент-движок. Видеотеку на сервере хранить не требуется. Проверка контейнера всё равно требует чтения некоторого объёма данных; это ограниченный временный буфер, а не постоянное хранение фильма.

Один видеофайл может содержать несколько озвучек, а одна озвучка — существовать во многих раздачах. Поэтому варианты нельзя считать по числу магнитов или склеивать только по языку. Отдельное меню аудиодорожек пользователю не нужно; автоматическое применение конкретной дорожки под единым выбором качества/озвучки нужно сохранить.

При отсутствии надёжного названия студии нельзя обещать LostFilm по одному русскому языку дорожки. Сначала используются проверенные метаданные, затем разбор названия как подсказка. Неизвестная дорожка получает честную подпись, а не придуманную студию.

Для HTTP/HLS и торрентов используется один пользовательский список, но разные адаптеры доставки. Наличие HTTP/HLS в целевой схеме не означает, что в этот PR уже подключены такие поставщики.

## Состояние реализации и порядок дальнейших работ

В 0.7.4 уже есть серверный поиск кандидатов, постепенная пагинация, фильтрация известных карт другой серии, ограниченное ожидание первых байтов и единое видимое меню качества/озвучки. Удалено отдельное меню аудиодорожек. Варианты пока группирует локальный адаптер; отдельного серверного постоянного индекса файлов и дорожек нет. Текущая нормализация студий по тексту не заменяет проверку контейнера.

Приоритеты:

1. Перенести готовые группы просмотра на сервер: стабильные ID вариантов и резервные источники вместо списка сырых описаний.
2. Независимо искать отдельные серии и сезонные сборники, включая случай, когда точные результаты уже найдены. Сейчас общий поиск используется как fallback при отсутствии точных кандидатов.
3. Создать постоянный индекс файлов и сопоставлений серий; сохранять результаты ограниченной проверки метаданных торрента.
4. Добавить внутренний селектор дорожки к варианту просмотра. Использовать уже получаемые плеером данные контейнера и ограниченную фоновую проверку популярных файлов; не добавлять тяжёлый ffmpeg в TV только ради сканирования списка.
5. Разделить наблюдаемую доступность, возможность подключения и фактическую устойчивость воспроизведения. Ранжировать совместимость, точность серии/озвучки и свежие результаты запуска, а не только сиды.
6. Подбирать временной запас буфера по скорости/битрейту и пределу памяти. Проверять измерениями; не объявлять фиксированный процент универсальным решением.
7. Сохранять студию и качество для следующих серий. При автоматической замене источника сохранять озвучку; изменение пользователем предпочтений не скрывать.

Проверки при реализации: серия из полного сезона; несколько сезонов в одном торренте; несколько русских студий внутри одного MKV; одна студия в нескольких раздачах; несовместимый кодек; мёртвый источник с устаревшими сидами; смена качества с сохранением позиции; запоминание озвучки следующей серии; частичные результаты и поздние источники; ограничение времени и памяти. Проверку первых байтов необходимо дополнить измерением первого кадра и устойчивого чтения на реальном телевизоре.
